Analysis and modelling

What we understand before drawing anything: the client’s requirements, turned into models the whole team can read.

  • Listen to the client: the problem to solve, who uses the service, for what, on which device
  • Analyze what already exists before proposing a solution
  • Model in UML: use cases, classes and sequences
  • Break the requirements down into milestones and tasks, so everyone knows what comes next

  • GitHub Projects

Design and experience

  • Check readability and accessibility: contrast, sizes, keyboard, mobile first

Process

From idea to deployment.

How I work, read like a Git history.

$ git log --oneline --graph --reverse

  1. Understand the requirements

    9a0c3e8feat(analysis)

    I listen before proposing anything: the problem to solve, the users, their devices and their connection. I analyze what already exists before opening the editor.

  2. Architect and plan

    3e4f2a1feat(architecture)

    Architecture and technical choices, then milestones and tasks on GitHub Projects: everyone knows what comes next.

  3. Model the data

    2f6b5d1feat(data)

    Schema, constraints and indexes (UML, DBML) before the first line of interface code. A clear database saves months of fixes.

  4. Design and prototype

    5d27b9efeat(design)

    User journeys, mockups and a clickable prototype in Figma, in light and dark themes: we test the experience before writing the code.

  5. Build screen by screen

    e91a7c2feat(product)feature/product

    The API and the components move forward together on a dedicated branch, tested on mobile at every step.

  6. Test and deploy

    4b8d0f3merge

    Tests, pull request review, deployment, reliable forms, authenticated email and Google indexing.

  7. Maintain and grow

    7c1e2a9refactorHEAD → main

    Feedback from real users decides what comes next: fixes, performance, scaling.
